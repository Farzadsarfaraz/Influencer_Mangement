# Implementation Roadmap

Each milestone ships something runnable and reviewable — no milestone ends with dead code sitting unconnected. Order matters: later milestones depend on the data-access and permission patterns established in Milestone 1.

## Milestone 1 — Foundation ✅
Env config, Prisma 7 setup (driver adapter + `prisma.config.ts`), Prisma client singleton, Auth.js v5 with credentials provider + JWT sessions + revocation-aware `getCurrentUser` + `proxy.ts` portal gate, base layout shells for all three portals, shadcn/ui installed and themed, Docker + docker-compose (Postgres/Redis/MinIO/Mailhog), GitHub Actions CI (lint/typecheck/test/build), seed script with one user per role. **Done when:** `docker-compose up`, `prisma migrate dev`, `npm run dev`, and a user can sign in and land on the correct portal shell for their role.

## Milestone 2 — Brands, Teams & Influencer CRM ✅
Brand CRUD (agency), BrandMember management + client invite flow (issues an activation link — email delivery lands in Milestone 6), Team CRUD, Influencer CRM (profile, social accounts, tags, notes, invite-to-portal) with list/detail views and search/filter. **Done when:** an agency admin can create a brand, invite a client user scoped to it, and build out an influencer roster. Lint/typecheck/tests/build all green; live migration against the real database is pending network access outside this sandbox (see below).

## Milestone 3 — Campaigns, Flights & Assignments ✅
Campaign CRUD + status workflow (`lib/workflow/campaign.ts`, unit-tested), Campaign Flights, Assignment creation + status workflow (`lib/workflow/assignment.ts`, unit-tested), deliverable definition. Every status change writes both an `ActivityEvent` and an `AuditLog` entry inside the same transaction as the update. **Done when:** an agency manager can stand up a campaign, add flights, and assign influencers with deliverables. Lint/typecheck/tests/build all green.

## Milestone 4 — Content Submission & Approvals ✅
File upload pipeline (presigned S3/MinIO PUT URLs via `/api/uploads/presign`, permission-checked before signing), content submission versioning (one immutable `ContentSubmission` row per revision), two-stage approval workflow (`lib/workflow/content-submission.ts`, unit-tested: INTERNAL approval hands off to CLIENT, only CLIENT approval finishes it), threaded comments shared across all three portals. **Done when:** an influencer can upload content, it flows through internal then client approval, with comments at each stage. Lint/typecheck/tests/build all green.

## Milestone 5 — Customer & Influencer Portals ✅
Customer portal: brand-scoped campaigns list/detail (progress KPIs, approved deliverables with downloads, activity timeline), Files page. Influencer portal: invitation accept/decline, briefing display, messaging (per-campaign thread, shared component reused on the agency side), payments status. **Done when:** both external roles have a complete, scoped, non-leaky view of their own data — verified every customer read is scoped through `getBrandsForUser`/brandId filters and every influencer read/write checks `influencer.userId === session.user.id`. Lint/typecheck/tests/build all green, 32 routes.

## Milestone 6 — Workflow Engine, Notifications & Messaging ✅
Domain event emitter (`lib/events`, dispatched via Next's `after()` so it never adds latency to a Server Action's response), wired into every status-changing action (campaign/assignment transitions, content submission, approval decisions, messages, payments). BullMQ worker process (`worker/index.ts`, `docker/Dockerfile.worker`) running an email queue and an hourly deadline-reminder job scheduler. Real email delivery via nodemailer + a React Email template. In-app notification center (bell in the portal header, polled via React Query, backed by the existing `Notification` model). Campaign/Assignment/ContentSubmission transition tables and messaging were already in place from Milestones 3–5. **Done when:** a status change or new message produces both an in-app notification and a queued email, without slowing down the action that triggered it. Lint/typecheck/tests/build all green.

## Milestone 7 — KPI Dashboards & Reporting ✅
Metric snapshot ingestion (manual entry form + CSV paste-import), campaign KPI dashboard with a reach/impressions/engagement chart (recharts, validated CVD-safe palette) and a per-influencer breakdown table, the same read-only KPI view surfaced on the customer campaign page. Async report generation: a `Report` row is created `PENDING`, a BullMQ job renders a campaign-summary PDF (`@react-pdf/renderer`) or Excel workbook (`exceljs`), uploads it to object storage, and flips the row to `READY` — polled from the UI via React Query, downloaded through an access-controlled route rather than a raw public S3 link. **Done when:** an agency user can log/import metrics, see them on a chart, and download a generated report once it's ready. Caught and fixed a real bug along the way — Postgres treats `NULL != NULL`, so the campaign-total metric rows (no influencer/platform) couldn't be upserted through the compound unique key; replaced with an explicit find-then-write. Lint/typecheck/tests/build all green.

## Milestone 8 — Administration ✅
User management (list/search, role changes and suspend/reactivate — both bump `tokenVersion` so a revoked session loses access immediately, not at next JWT expiry), a super-admin-only guard on granting/revoking `SUPER_ADMIN`, feature flags, application settings, an audit log viewer, and a roles reference page. `ActivityTimeline` extracted as a shared component and reused on campaign, brand, and influencer detail pages (customer campaign page refactored onto it too). All of `/agency/admin/*` and `/agency/audit-log` gated by `ADMIN_ROLES`, independent of the broader agency-portal gate.

## Milestone 9 — Hardening ✅
Redis token-bucket rate limiting on sign-in (per-email and per-IP) and invite-accept. Pagination added to Users, Audit Log, Brands, Campaigns, and Influencers. DB index audit added 4 indexes that were missing for real query patterns (`Deliverable(status, dueDate)` for the reminder sweep, `ApprovalRequest(stage, decision)` for approval queues, `Conversation(influencerId)` for the influencer's message list, `User(status)`) — **not yet migrated**, since this sandbox can't reach the live database; run `npx prisma migrate dev` to generate and apply. RBAC integration tests against the real data layer (brand isolation, assignment-ownership) — skip gracefully (not fail) when no DB is reachable. Playwright E2E specs for sign-in and cross-portal 404s. Accessibility pass fixed several real gaps: icon-only buttons/triggers with no accessible name (notification bell, user menu), and search/filter inputs relying on `placeholder` alone instead of an associated label. CI extended to build and push both Docker images (app + worker) to GHCR on `main`, plus a deploy job stub — intentionally not wired to a specific host per the infra-agnostic design in docs/ARCHITECTURE.md §14.

Along the way, fixed a real cross-cutting bug: `lib/data/*`'s `import "server-only"` had never been resolvable outside Next.js's own bundler (the package isn't in package.json at all — Next special-cases the bare specifier) — anything that tried to test that code through Vitest would throw unconditionally. Installed the package for real and aliased it to its own no-op build in `vitest.config.mts`, the standard fix for testing server-only Next.js code.

---
Milestones ship sequentially, one at a time, each reviewed before the next starts — per the working agreement for this project.
